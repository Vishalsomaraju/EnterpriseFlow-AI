# SecurePush Integration

## Overview
This document defines the integration boundary between EnterpriseFlow AI and the SecurePush scanning service.

## Integration Principle
> [!NOTE]
> Keep the SecurePush integration deliberately small. Do not duplicate SecurePush's scanning logic inside EnterpriseFlow. Instead, create an isolated adapter around it.

## Architecture

The integration exists strictly as an adapter within the security module.

```text
security/
└── SecurePushAdapter
```

If SecurePush updates its API or scanning logic, only the adapter needs to change; the rest of EnterpriseFlow remains unaffected.

## Pipeline and Data Flow

The SecurePush integration operates as a discrete step in the Bob Implementation Pipeline, right before Human Review.

### 1. Input
The input sent to SecurePush is strictly the code changes generated by Bob.
- **Payload**: Git diff / changed files.

### 2. SecurePush Scan
The external SecurePush service performs the scan.

### 3. Output
The adapter parses the raw response from SecurePush into a standardized format.
- **Payload**:
  - `findings`: List of specific security issues found.
  - `severity`: Standard severity rating (e.g., Low, Medium, High, Critical).
  - `risk`: The calculated risk score.
  - `status`: Raw status.

### 4. EnterpriseFlow Action
EnterpriseFlow takes the parsed output and applies governance rules to determine the build's security status.
- **Result**: `PASS` | `WARN` | `BLOCK`

*A `BLOCK` result prevents the build from being approved in Human Review until the security findings are addressed.*
